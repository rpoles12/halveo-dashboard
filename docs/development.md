# Development and publishing

## Requirements

- Node.js 24 (`.nvmrc`). The delivery was built with Node 24.22.3.
- pnpm 11.25.0 (`packageManager` in `package.json`).
- An internet connection for a clean dependency installation, Google Fonts and the initial Playwright browser download.

No `.env` file, service account, API key or database is required. Do not commit credentials if future services are added.

## Local workflow

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Vite uses port 4173 unless unavailable. Use the URL printed in the terminal.

```sh
pnpm check
pnpm build
pnpm preview
```

Type checking uses `--noEmit`, so it does not create generated Vite configuration files or TypeScript build-info files. Vite generates `dist/`, which is ignored by Git.

## Browser validation

```sh
pnpm exec playwright install chromium
pnpm build
pnpm test:smoke
```

The smoke script starts and closes its own loopback preview server. Each run gets a new browser context, so it cannot modify your normal browser's saved demonstration state. It checks filters, operations search and empty state, methodology, anomaly inspection, action creation and status transitions, persistence after reload, CSV content, Data Sources, compact mode, guided demo and overflow in all eight views at three widths.

To select an already installed Chrome in PowerShell:

```powershell
$env:PLAYWRIGHT_CHANNEL = 'chrome'
pnpm test:smoke
pnpm capture
```

`test-results/smoke.json` contains the latest successful local test result and is ignored by Git. `docs/delivery.md` records the validation shipped with this handoff. CI is configured in `.github/workflows/ci.yml`; it is not a hosted deployment workflow.

In restricted environments where loopback networking is unavailable, set `HALVEO_FILE_PREVIEW=1` before running the browser scripts. This serves the local `dist/` bytes through Playwright request interception at a virtual `halveo.local` origin and blocks external requests. It does not test an actual HTTP deployment, and Google Fonts will use the app's fallback. Normal local development and CI use the HTTP preview by default.

## Recreate portfolio media

```sh
pnpm build
pnpm capture
pnpm cover
```

Capture uses a fresh context, a 1920 × 1080 desktop viewport and a 390 × 844 mobile viewport. Reduced motion makes charts and figures settle predictably. Images are written to `docs/media/`; provenance and dimensions are recorded in `captures.json`. The overview includes both viewport and full-page variants.

Cover composition reads `docs/brand/cover-background.png`, the original wordmark and the overview screenshot. It produces `cover.png` at 1920 × 1080 and `social-preview.png` at 1280 × 640. The generated background is retained, so regenerating it is not necessary.

The pre-existing dashboard GIF and MP4 are curated source deliverables, not regenerated by this repository's scripts. See [demo](demo.md) and [credits](credits.md).

## Reset the interactive demo

In browser developer tools, with the local dashboard open:

```js
for (const key of ['halveo-actions', 'halveo-compact', 'halveo-tour']) {
  localStorage.removeItem(key)
}
location.reload()
```

This affects only the demonstration state for the current browser origin. The action JSON currently has no schema validation or migration; resetting these keys also recovers from malformed saved data.

## Static hosting

1. Install dependencies using the lockfile.
2. Run `pnpm build`.
3. Publish the contents of `dist/` using the static host of your choice.

The app does not need a server runtime or a route fallback because view switching does not change the URL. Relative asset paths support hosting below a repository subdirectory. Serve over HTTP rather than opening `dist/index.html` directly. No domain or public demo URL has been created for this delivery.

For GitHub Pages, deploy the generated `dist/` artifact with a Pages deployment workflow or your chosen publishing mechanism; the included CI only validates. Configure a GitHub repository social preview using `docs/media/social-preview.png` if desired.

## Git handoff

The repository content deliberately excludes installed dependencies, build output, generated compiler files, design-editor working files, temporary helpers and duplicate media exports. The original branding workspace is retained outside this delivery.

The requested destination already contains a `.git` directory according to the readable folder listing. Preserve that directory and its existing remote/history when copying the delivery. Inspect it locally before creating a commit:

```sh
git status
git remote -v
git add .
git commit -m "Prepare Halveo dashboard portfolio repository"
git push
```

The final `git push` assumes the destination repository already has a remote and upstream configured. This delivery does not invent a remote URL, overwrite history or publish anything on your behalf.
